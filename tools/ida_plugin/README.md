# EE Hex-Rays lifter plugin

`ee_mac_lifter.cpp` — an IDA/Hex-Rays plugin that fixes three places where
IDA does not model the PS2 Emotion Engine, each of which otherwise produces
opaque `__asm{}` islands in the pseudocode this campaign uses as
reconstruction reference (`docs/ida_headstart/`, generated by
`tools/ida_headstart.py`).

## Status

| Fix | State | Notes |
|---|---|---|
| FPU accumulator chain (`adda.s`/`madd.s`/…) | **works** | validated on retail `0x0048aff0` |
| COP0 `bc0f`/`bc0t` mis-decode | **works** | stock r5900 decodes these as a bogus `mfthc1` |
| MMI `pcpyld`/`pcpyud` | **written, unbuilt** | validated on `func_003a29f0` before the SDK was lost |
| MMI generic helper calls | **removed — regressed** | see below |
| `sq`/`lq` callee-saved spills | **not fixed** | biggest remaining defect; approach identified |

## Not currently built or installed

The IDA SDK needed to compile this is **not shipped** with IDA Pro
(`~/ida-pro-9.4/include` contains only `defs.h` and `arm_sys_reg.h`) and the
SDK checkout used to build the previous `.so` was destroyed by a `/tmp`
wipe. The source lives here, in the repo, specifically so that cannot
happen again — at one point a built `.so` was installed with **no
recoverable source**.

To rebuild: obtain the IDA 9.4 SDK, build as a plugin against
`hexrays.hpp`, and install the `.so` into `~/ida-pro-9.4/plugins/`.

## Acceptance test — mandatory before installing any build

A microcode filter that asserts something the decompiler's own invariants
disagree with does not fail loudly; it silently turns working functions into
decompile failures. Both of the failed attempts here did exactly that.

Run a **controlled before/after** over the affected function population and
require that failures do not increase from the no-plugin baseline:

```
# with the plugin removed from ~/ida-pro-9.4/plugins/, then with it installed
~/idavenv/bin/python3 p4_mmi_check.py
```

Measured baselines on the retail binary (`orig/SLUS_217.82`):

- functions containing MMI: **153** → no-plugin baseline **153 ok / 0 fail**
- functions containing `sq`/`lq`: **5100**

### Why the MMI helper tier was deleted

It emitted every non-`pcpyld` MMI opcode as an intrinsic helper call built
from a hand-constructed `mcallinfo_t`. Spot checks looked good. The control
run was decisive:

```
without plugin  : 153 ok,  0 failed
with helper tier:  82 ok, 71 FAILED
```

It was deleted outright rather than left commented out, so it is not
re-enabled casually.

## The `sq`/`lq` problem (largest remaining, unfixed)

Measured over the retail binary:

- functions containing `sq`/`lq`: **5100** (~33× more than MMI)
- of those, decompiled with an `__asm` island: **5031**

It is *not* just cosmetic prologue/epilogue noise. Sampling 400 functions
containing `sq`/`lq` but no MMI:

- island confined to prologue/epilogue: **140**
- island intruding into the function body: **260 (65%)**

Two prior `microcode_filter_t` attempts (narrow `dt_byte16`→`dt_qword`; emit
raw `m_stx`/`m_ldx`) both crash Hex-Rays with `MERR_INTERR` — 239 crashes
across a 1725-function batch — because `analyze_prolog()` runs *before* any
microcode filter and builds a frame-slot-width model from the raw
`dt_byte16` operand that the filter then contradicts.

**The untried approach:** don't *lift* these instructions — a callee-saved
spill has no meaning in C and should be **elided**, like any ordinary
`sd $s0, off($sp)` prologue save. Hex-Rays has a channel for exactly this,
`get_ignore_micro()`/`set_ignore_micro()` with `IM_PROLOG`/`IM_EPILOG`
(`codegen_t` even carries the per-instruction value). Marking a callee-saved
`sq` as `IM_PROLOG` and its matching `lq` as `IM_EPILOG` makes the
decompiler skip microcode generation for them entirely — sidestepping the
prolog analyzer's width model instead of contradicting it.

Conservative identification rule: a `sq $r, off($sp)` where `$r` is
callee-saved *and* there is a matching `lq $r, off($sp)` from the same
offset is a save/restore pair by construction. Only mark those; a `sq` doing
real work mid-body must never be marked.

`set_ignore_micro`/`IM_*` are **not** exposed in IDA 9.4's Python API
(`ida_hexrays` exports only `NORET_IGNORE_WAS_NORET_ICALL`), so this cannot
be prototyped from idalib and requires the C++ SDK.
