## Levers

- **Case order.** The sparse `switch ((u8)p[1])` has cases 0x11 to 0x22 plus
  0x97. MWCC compiles it as a `beq` chain that tests the labels in reverse
  source order and lays out the bodies in source order. The source order is:

  0x11, 0x12, 0x13, 0x14, 0x15, 0x16, 0x17, 0x18, 0x22, 0x21, 0x19, 0x97,
  0x1A, 0x1C, 0x1B, 0x20

  The nested `p[0xB3]` and `p[0xB6]` switches follow the same pattern.
- **`#pragma opt_lifetimes on`** (scoped with push/pop). Retail gives each loop
  its own register (`$s1`, `$s2`, `$s3` or `$s4`) and reuses `arg0`'s `$s1`
  where the task pointer is dead. Adding the pragma took the count from 170 to
  20 edits. The pragma sweep with `opt_loop_invariants`, `opt_propagation` and
  `optimization_level 3` found nothing better.
- **A separate `selected2` local for the 0x16 rescan.** 0x14 and 0x16 run the
  same reward scan. Under lifetimes, sharing one `s8` local swapped the index
  and result registers in 0x16 (-10 edits).
- **`FclCombineRow` (10 bytes at `+0xC4`) for the selected-row reads.** This
  gives `addu idx, p`. Pointer arithmetic `p + idx * 10` gives `addu p, idx`.
  An array-index form broke the offset folding and grew the object.
- **The 0x1A loop passes the `s16` row id to `func_00318840`'s `s8` slot.** The
  resulting narrowing `lb` restores retail's argument order: the load comes
  before `move $a0`.
- **`off = i * 2` at the top of the two drawn 0x18/0x20 loops.** Retail
  computes the offset into `$s2` before the `func_002b2970` call.
