## Source recovery

The complete retail assembly, current guarded C, full Ghidra and IDA
bodies, actual callees and callers, and earlier Fcl notes were inspected.
The apparent register-allocation floor partly came from an inconsistent
getter declaration: draw declared `func_0034ae50` with an `s64` slot while
its actual provider and combine callers use `s8`. The narrow getter
contract reproduces the separate conversions in both entry loops.

The final renderer contract is:

```c
void func_0031d630(u8 *task, s8 slot, s8 first, s64 second, s64 entry_mode);
```

The second selector and entry mode are converted to signed bytes at their
individual uses. Narrowing those incoming formals too produced the same
renderer instructions but changed the argument-load order in the already
exact `func_003233d0`. Retaining their wide incoming contract preserves
both functions exactly.

Ten real color constructor outputs have separate homes. Descriptor colors
are copied as four byte channels after each relevant lookup. The packet
passed by value to `func_002ba970` uses the existing `PackedColor` union
pattern. The paired resource opacity writes share their unsigned-byte
assignment result, retaining the retail `0xff` value and intermediate
mask. Per-entry opacity values are unsigned bytes rather than negative
signed-byte spellings.

The two entry loops have separate signed-short counters. Resource indices
are derived in branch-local 32-bit values and narrowed at lookup calls.
The selected loop snapshots its byte row before deriving the task and
list row addresses. `opt_propagation off`, restored immediately after this
function, preserves that real snapshot: the otherwise identical candidate
had only a two-instruction initialization-order difference. No broad
optimization sweep was needed for this final step.

The list row uses the target's defined 32-bit `uintptr_t` address form for
the row offset, then byte-pointer arithmetic for the signed-short entry
index. This preserves the two distinct retail additions while retaining
the real twelve-byte row stride and field offset `0x14`. It introduces no
extra memory access. The final text draw uses the actual position
`(113, slot * 23 + 128)`, depth 43, packed selection color, and original
text/resource lookups.
