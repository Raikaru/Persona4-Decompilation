# Debug list-window controller: 0046f2b0

Recovered in `src/promoted/code1_0046.c` with MWCCPS2 b210 and the owning
file's ordinary `-O2 -Iinclude` build. The initial main-tree draft produced
4,064 bytes for the 3,936-byte retail window, with 593 alignment edits. The
accepted C produces **3,928 executable bytes and eight retail zero bytes**.

## Source and ABI recovery

- `sdkLbox.c::func_00470280` allocates the 0x190-byte controller, initializes
  its rectangle, row height and 0x2C-byte input state, and registers this
  callback. Four 0x40-byte vertices have the PS2 RenderWare screen-vertex
  layout. The 0x22C-byte entry and `void (void *)` selection callback follow
  `k_view.c` and the linked-list accessors in `code1_0047.c`.
- Each window theme uses two complete four-byte RGBA snapshots. Eight
  adjacent palette values at 0x00764134 through 0x00764150 and the mutable
  four-byte selection tint at 0x007641A8 are now named, bounded objects.
  Their GP-relative references and the existing constructor's four-byte
  copies independently establish the extents. The old floating-point
  locals merely transported these bytes and were not color components.
- Rectangle initialization and its consuming constructor call belong to
  one inline helper. A native `{ x, y, width, height }` initializer produces
  the compiler's byte-clear loop with the captured input dimensions still
  live. Returning an intermediate rectangle introduced a separate aggregate
  copy. Handwriting the clear retained a repeated 60-word allocation
  residual. The accepted helper immediately consumes its rectangle and
  both colors and returns the existing constructor's real window pointer.
- The render-state calls address the existing native RenderWare instance
  member and reload the registered callback at each invocation. A copied
  function pointer would incorrectly ignore a callback replacement.
- The four modifier selections are ascending conditional chains rather
  than switch dispatches. Integer entry updates explicitly wrap through
  `u32` before their signed bounds checks, matching the EE arithmetic while
  avoiding C signed-overflow behavior.
- The shared update-callback suffix follows every continuing state, with
  the signed `state > 2` threshold. State 5 returns immediately. The analog
  deadzone remains strict at -48 and +48. Integer and floating entry limits,
  callback descriptors, button priority and live post-callback reads remain
  distinct.

The only new optimization setting is function-scoped
`opt_loop_invariants on`. Removing it grows the body to 3,944 bytes and
introduces 73 alignment edits. It hoists the invariant preparation for the
four unsigned color conversions; source-level byte counts retain defined
unsigned decrement arithmetic. The setting is enclosed by push/pop.

## Whole-owner proof

Production verification reports **57 MATCH and one unchanged ASM fallback**.
The remaining fallback is the separately guarded movie controller
`func_00468ff0`; it earns no C credit from this recovery.

Independent relocation application establishes:

- all **74 target code relocations** reach their retail targets
- all **905 code relocations** across the 58-function owner are exact
- all **57 sibling byte images and canonical relocations** are unchanged
- the four owned jump-table sections are exact: 116 bytes at 0x00756580,
  48 at 0x00756670, 36 at 0x00756790 and 24 at 0x007567C0
- there are no unowned executable helper definitions; the native GNU object
  and MWLD text splitter both accept the complete placement
- the production eligibility classifier accepts the owner and its data

A separate `NON_MATCHING` build, using the existing CRI header directory as
an include path, preserves every sibling measurement and matches this target.
The movie draft remains nonmatching. No provider signature or guarded movie
source was changed.

The nine new curated data symbols are merged with the repository's
`recover_symbols` parser and address-ordering rules while preserving every
pre-existing recovered-address line. This is an incremental curated merge,
not a claim that a full compiler-wide symbol scan was rerun.

## Behavior checks

`test_window_controller_contract.py` extracts the actual active function and
its construction helper. The native 32-bit fixture compares them with an
independent state-machine oracle using typed callbacks and guarded storage.
Both O0 and O2 pass **20,288 cases**, including:

- all states, valid and invalid themes, enable values and visibility gates
- all eight flag combinations, six entry kinds and sixteen modifier masks
- button precedence, null selections, optional callbacks and argument pairs
- integer/real bounds, exact floating bounds and signed integer wrap edges
- analog values immediately below, at and above both deadzone boundaries
- constructor, readiness, render-setter, drawing, input and selection
  callbacks that mutate live state before subsequent reads
- complete output state and entry bytes, untouched guards, ordered call
  traces, rectangle arguments, colors and submitted quad vertices

The local GCC/i386 runs enable undefined-behavior, bounds and float-cast
traps. The committed test uses the project's Clang native32 runner in CI.
This validates source behavior and ABI under mocks, not execution of PS2
hardware or a gameplay session.

Thirteen deliberate mutations are detected, covering palette copies,
enable gating, live state advancement, vertex alpha, row coordinates,
analog boundaries, modifier precedence and largest step, integer and real
limits, callback payloads, the shared update gate, and a frozen render setter.

Lint has no errors. Its new pragma advisory is supported by the ablation
above; the existing owner-wide declaration advisories are unchanged and
outside this target. The whole-repository name check still reports the 17
pre-existing pending substitutions in `y_fclCombine.c` and `effLineNova.c`,
with no occurrence in this owner. Retail loadable-image and ELF hashes and
actual C linkage are acceptance checks for the exact published CI commit.
