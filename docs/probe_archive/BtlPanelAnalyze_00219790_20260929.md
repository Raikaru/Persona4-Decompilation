# Battle analysis panel recovery, 00219790

The panel draws four independently animated sections: the character name and
statistics, affinity icons, the skill list, and its footer. Their counters and
positions have separate lifetimes. Reconstructing those phases reproduces all
4,120 instruction bytes in the 4,128-byte retail window; the remaining eight
bytes are zero alignment. The complete `src/Battle/btlPanelAnalyze.c` owner
retains its seven previous C matches and adds this eighth match.

## Interface and observed state

The first incoming task argument is unused. The second points to a panel with
flags at 0, an unsigned frame halfword at 4, a unit context pointer at 8, and a
task handle at 0x10. The frame and enemy index are promoted to signed words
before the arithmetic and callback calls; the stored values remain unsigned
halfwords. The work flags and panel flags independently gate rendering.

The local statistic renderer's C signature interleaves its existing arguments
as `(work, value, x, kind, y)`. Its definition and all four callers use that
order. The EE inputs remain `a0=work`, `a1=value`, `a2=kind`, `f12=x`, and
`f13=y`. No argument is added, removed or retyped. The provider still matches
its retail body, and a repository search found no other C callers
or declarations of that function.

The skill count provider returns a word; the displayed count is its low
halfword. Its companion provider returns the underlying byte pointer, which
the panel views as halfword skill identifiers. Both declarations agree with
their existing definitions in the data calculation owners.

## Source reconstruction

The angle expressions divide the elapsed phase first, then multiply by the
quarter-turn angle. Reassociating that calculation changes the floating-point
instruction sequence. The name, affinity, skill and footer fades each have
their own live coordinates. The skill panel has a two-dimensional origin:
its horizontal offset slides while the vertical origin remains zero.

The affinity table is observed through a pointer to the selected halfword,
including after callbacks. The enemy-kind table is likewise read at each
observed callback boundary. Calculated label and background positions are
carried to their displayed coordinate values before those observations.

The footer computes its next line offset separately from the final translated
position. This preserves the two arithmetic operations and does not contract
them into one multiply-accumulate. The known-skill count is captured once
after the two providers, rather than masked on every iteration.

The 128-byte name buffer and three 64-byte concealed-panel vertices are real
objects. Their allocation matches the retail frame without artificial padding
or uninitialized inputs. The draw callback consumes the initialized position,
depth, reciprocal scale and color fields of those vertices; unused reserved
fields are not read by this routine.

## Retained evidence

The campaign directory is
`build/first-party-finish-20260929/battle-worker4/`.
`00219790/consistent-statistic-x-before-kind/owner-verification.json` records
the first complete owner check, including named data relocation validation
and resolved call targets. `00219790/clean-provider-contracts/` retains the
cleaned C, compiler log, object, hashes and zero-difference comparison.
`prepare_panel_recovery.py` and `install_panel_recovery.py` record the final
cleanup and the checked installation. The baseline owner had seven MATCHes
and one ASM fallback.

The installed owner is verified by `panel-verify-final.json`. Its task and
skill-name imports also use the canonical provider declarations; those changes
preserve all eight matches. The source linter reports no integrity errors;
the existing camera-import declaration advisories are outside this recovery.

`tests/test_btl_panel_analyze_behavior.py` executes the actual recovered body
with real 32-bit layouts. Clang 19, undefined-behavior and bounds traps, and
both `-O0` and `-O2` passed 48 scenarios each. The scenarios cover disabled
panels, phase boundaries, statistic clamping and row arguments, concealed
vertices, the two-column skill grid, zero and narrowed skill counts, and
callback mutation of kind, affinity and depth data. Three deliberate changes
to a statistic row, grid column width and table observation were all rejected
by the fixture. The native tests ran through WSL with
`PATH=/usr/lib/llvm-19/bin:/usr/bin:/bin` and the existing native32 support.
