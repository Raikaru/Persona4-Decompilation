# Title logo draw 00222210: rewrite at 64 edits

`func_00222210` (2832-byte window, 705 instructions, frame 0x120) stays
INCLUDE_ASM. `LogoDraw_00222210_20260926_body.c` is a fresh rewrite from the
retail listing. It scores 64 fnalign edits (700/705 instructions, +4
reloc-only for the two pooled gp literals). The guarded draft in
code1_0022.c scores 277.

Structure read from the listing:

- The four sprite calls (0x1D from `work+0x54`, then 0xB2/0xB3/0xB3 from
  `work+0x50` at x offsets 207/300/314 minus 6) are one static inline helper,
  expanded twice. Retail has two separate sets of by-value parameter copies:
  origin at 0xE0/0xD0 (ld/sd), offset at 0xE8/0xD8 (ld/sd), and the 4-byte
  colour at 0x118/0x114 (lwc1/swc1). The rotation centre arguments are
  `(s16)(origin - pos)`.
- The helper parameter order `(work, offset, color, origin)` gives retail's
  copy order and slots (64). The other five orders give 68-83.
- `ofs` must be declared before `pos` (ofs at 0x108, pos at 0x100). The two
  triangle fills store into `ofs`.
- `fGpffff8384`/`fGpffff8388` are the pooled literals 562.5f and 421.5f.
- The `adda.s $zero-reg, c` + `madd.s` pattern is `0.0f + c + k * t` (b210
  does not fold `0.0f + c`). The first fill's 265/375/281 are converted at run
  time (`(f32)375`), and the second fill's 348/292/220 are float literals.
- `opt_loop_invariants on` is needed. Retail hoists the colour constants of
  both fill loops, and hoists the origin copy, colour copy, `origin.y` and the
  g/b/a bytes out of the 3-iteration logo loop (142 -> 72 with it).
- Fill loops use block-scoped counters and `u8 *p = colors[j]` (retail keeps
  the index in `$a0`/`$a2` and addresses `sp + i*4 + 0xF0`).

Residual (all in the logo helper, both expansions):

- Retail recomputes `origin.y - pos.y` (`sub.s $f0, $f22, $f20`) before
  every call. b210 CSEs it into one saved register. That costs one float
  register, which then swaps fade0/fade3 (`$f24`/`$f23`), the loop counter
  and `res` (`$s6`/`$s5`), and renames pos.x/pos.y/origin.y.
  Retail keeps `origin.y` in a register while reloading `origin.x` from the
  copy after every call.
- Shapes tried that still CSE the diff (all 63-64, or worse): a per-sprite
  struct `p` with `p.y = pos.y`; an inner inline per-sprite helper taking
  origin by pointer, by scalar floats, or by value (by value adds stack copies,
  283); no `pos` variable, with `offset.y + origin.y` written in every call
  (63); an explicit `f32 oy = origin.y`; implicit s16 argument conversion
  instead of casts; and `opt_common_subs off`, which breaks everything else
  (299/525).
  Micro tests (tools/micro_codegen.py) confirm that b210 CSEs this
  diff across calls in every scalar form tried. The only shape that
  recomputes it is when the y operand is re-read from a memory-backed struct
  copy (`q = p`), and that adds stores that retail does not have.
- Declaration-order changes of the five fade/scroll floats do not fix the
  f23/f24 swap on their own (64-72).
