# Debug text-grid renderer 0044f720

`src/sdkDbprt.c` now recovers the 40-row, 53-column debug text-grid renderer
in ordinary C. Its configured MWCCPS2 b210 compiler at `-O2 -Iinclude` emits
876 bytes in the 880-byte retail window. All 17 relocations resolve exactly;
the final four retail bytes are zero alignment.

The renderer begins a camera update, saves and disables fog, binds the font
raster, and initializes four immediate-mode vertices. Each non-space character
selects one cell of the sixteen-column glyph atlas and draws an eleven-pixel
rectangle on the twelve-pixel text grid. It then draws the other queued debug
content, restores fog, and ends the camera update. The saved state is number
14, `rwRENDERSTATEFOGENABLE`, as defined in the Sky RenderWare header.

## Source model

The vertices are complete 64-byte records with position, texture coordinates,
reciprocal depth and four floating-point color channels. The remaining camera,
normal and padding fields retain the documented Sky vertex layout; the routine
does not initialize fields that the original renderer leaves untouched. The
texture coordinates occupy a separate complete eight-float array.

The incoming character is normalized as an unsigned byte. A small signed
remainder helper expresses the sixteen-column atlas lookup and preserves the
compiler's actual conversion order. The source uses the existing private
`sGrid[40][53]`, whose complete 2,120-byte placement at `0x008BF720` is also
independently established by the already matching `H_Dbprt_Flush` references.

The last three instruction differences were the ordering of the white color
constant and the near-screen-depth load. The near depth is a field of the
render-device object at `0x008872F0`, not an independent small float array.
Its offset eight and the full device layout follow
`include/rw/plcore/badevice.h`; accessing that real owner field under scoped
`opt_loop_invariants on` reproduces the retail initialization order. Local
constant spelling, declaration-order and compiler-stage variants did not fix
that discrepancy.

The camera begin/end declarations now agree with the existing
`u32 (u32 camera)` providers. The state callbacks retain their actual integer
state and pointer-value interface. No provider implementation was changed.

## Complete object placement

The four existing private state words had previously been emitted in descending
retail-address order, which made the complete owner ineligible for linking.
Their source declaration order now makes b210 emit them consecutively at
`0x00764ACC`, `0x00764AD0`, `0x00764AD4` and `0x00764AD8`. These are the queued
text head, camera, temporary image and font raster. No state object, initializer
or allocation was added. All six neighboring functions retain their native
bytes and relocation meanings, and every allocated data payload is unchanged.

The real linker eligibility path accepts the reviewed complete owner without
new symbol aliases or changes to build rules. The independent target proof
also checks its referenced camera/raster words and the entire text grid
against retail zero-filled storage. Installed verification and full-image
source-link checks are retained separately from candidate discovery.
