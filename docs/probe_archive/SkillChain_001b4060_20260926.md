# Skill 0x13D packet chain `001b4060` recovered, 2026-09-26

`src/promoted/code1_001b.c` `func_001b4060`: MATCH, 1488 bytes (the exact
window). The unit goes from 118 to 119 MATCH, and no other function in it
changed status. This replaces a `SKIP_ASM` draft (314 words, 9 instructions
short) that used a frame-offset struct.

The function queues skill 0x13D's presentation for the current action
(`W->0x170`). It sends a formation packet, the skill SE, two camera packets
and an effect packet, then a formation packet for the acting unit and a sound
state change. For every unit in the `W->0x178` list it queues: a result
display, a formation packet, a sound state change, a camera state 0x1B
packet, an optional down animation when the unit is dead and flag 0x200 is
set, a target result, an HP change (when non-zero) and a status packet. It
ends with three closing packets and `func_001d3e00(form)`.

Relocations: the gp work pointer (`iGpffffb3ac`) and the called functions
(`btlSoundCreateSkillSEPacket`, `btlCameraCreateSetStatePacket`,
`btlUnitCreateAnimPacket`, `datCalcGetHp/Sp`, `datCalcIsDead`, and others).

## What the old draft had wrong

- Every `+8` link read the packet's own `+0x58`. Retail reads the `+0x58` of
  the packet that the new one follows: the first formation packet for the SE
  packet; the SE packet for both formation packets; the per-unit formation
  packet for the sound, camera, animation and result packets; and the
  result packet for the HP and status packets.
- The first `func_001d6240` takes `action->0x30` twice, not the action
  pointer.
- `func_001b7080(0x13D)` goes into its own local. The draft overwrote `form`,
  which is still needed later.
- The camera packet's `+0x58` becomes `last`, which is the `+0x18` link of
  the next unit's formation packet and the `+8` of the three closing packets.

## Levers

- `datCalcGetHp`/`datCalcGetSp` are `u16 (int)` (their definitions in
  datCalc_grouped.c). The file-scope declarations said `s32 (u8 *)`, which
  dropped retail's `andi` on the return value (2 instructions short). This
  function is their only caller in the file.
- Packets that die before the next call go in `next` (retail moves them
  straight to `$a0`). Only packets whose `+0x58` is read later are held in
  saved registers (`packet`, `sePacket`, `unitAction`, `camera`).
- Locals are declared in retail's saved-register order, highest first:
  `maxSp, sePacket, unitAction, unit, last, form, packet, action` (`$s7`..`$s0`).
  With the reverse order the body is byte-identical apart from 71 words of
  register permutation.
