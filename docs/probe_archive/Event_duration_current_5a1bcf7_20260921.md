## Actual condition and shared call

In polygon mode 3, a nonnull previous key permits a Scene lookup. The resource
must also be nonnull before the unsigned duration at key+2 is read. A successful
lookup sets the real update-enable variable to one. A nonzero duration assigns
one to the same variable, which is consumed by the polygon-setter guard.

Both duration outcomes therefore keep the resource enabled and reach the same
setter once. The compiler removes the redundant assignment but retains the
retail `lhu`, zero test and shared branch destination at `00287760`. This is the
trailing redundant-state assignment mechanism documented in
`docs/first_party_matching_handoff.md:3165-3179`.

There is no expiry comparison or expiry action in this P4 path. The P3 donor's
expired-key return would change behavior and is not restored. The added C
condition has no dummy local, volatile access, assembly, synthetic side effect
or padding. The source marker remains immediately before the real definition.

consume a return. Resource and Event work are valid objects. Optional keys may
be null on the branches that handle their absence. Existing record extents,
alignment, valid cut-in indices and sequencer frame arithmetic remain required;

cut-in code initializes both signed halfwords before passing its packed word,

The recovery preserves the post-call slot reloads and unsigned 32-bit address
