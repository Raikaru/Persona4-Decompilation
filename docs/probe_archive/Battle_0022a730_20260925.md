## Levers

- **The parameter block is one 0x20-byte union** (`u32 words[8]` /
  `u8 bytes[0x20]`), the same shape the neighbouring packet builder uses.
  `func_001f0a10` fills it and the code then sets `params.words[3] = 0x100`.
  This restores retail's `sw 0x100, 0x7c($sp)` and the 0xA0 frame, with the
  union at 0x70 and the rotation centre `RwV3d` at 0x90.
- **Roster index as an inline helper returning `u16`.** Retail masks the
  index twice, once at the helper's return and once at the caller's use.
  Inside the helper, `node` has to be declared before `index`. The other
  order swaps `$v1`/`$a0` and costs 8 words.
- **Masks written as `&= 0xFFDF`** (and `0xFFF7`, `0xFFEF`) give `andi`.
  `&= ~0x20` gives `addiu -0x21` plus `and`.
- **`last` is not initialised.** Retail tests `$s1` after the first scan
  without ever clearing it. This is kept as retail's own behaviour, and the
  source comment says so.
- **Saved-register colouring by declaration order**, as in `matching.md`'s
  saved-register rule. The body was structurally exact at 50 words. The
  order `moveDelay, entry, delay, count, last, other, unit, target, move`
  took it to 8 words, and the helper's local order took it to 0. The second
  loop uses its own `other`/`target` names, not the first loop's
  `entry`/`unit`.
