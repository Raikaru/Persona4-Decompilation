What mattered (fnalign edits):

- The gp floats are pooled literals: pi/2, pi, -pi/2, 2pi, 0.1, 0.2, 0.3,
  0.4, 0.6. The 25.2 at -0x7D58 is `42.0f * 0.6f`. In the fixed-scale pair
  it comes from a variable (`size = 42.0f * 0.6f;`) so the `(s16)size`
  conversion stays at run time. Writing `(s16)(42.0f * 0.6f)` folds it to 25.
- Declaration order `ra, ry, fade, scale, size, level, fade2, rx` gives
  retail's FP registers across both arms. The first declared gets the
  highest register, and variables from the two arms share registers.
- The small-effect arm draws its random numbers into locals first (`ra`,
  `ry`, `rx`, in that order) and uses them afterwards. Retail makes all the
  RpRandom calls before any conversion.
- `(u32)(1.0f * r)` survives only through an inline parameter
  (`p4_0025_span(range, unit)`); a literal `1.0f *` is folded away.
- One shared `return 0` at the end, with `return 1` in each arm, gives
  retail's branch layout. Separate returns give an xori.
- In the second draw of the fading arm the random value goes through
  `level` first. Inline in the argument, the multiply by `fade` swaps its
  operands.
