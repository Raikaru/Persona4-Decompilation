## Fusion skill picker, `00312c60`

Owner: `src/Event/Fcl/fclCombineMisc.c`.
Selected body: `build/complete-20260921/fcl-independent/runs/wide-result/candidate.c`.
The same directory contains `fclCombineMisc.c`, `owner.o`, and all native evidence.

Full retail assembly exposes substantive width errors in the old guarded draft:
pool skill IDs and inheritance coefficients are signed halfwords, while the
allocated weight array contains 32-bit words. The old draft used byte loads for
the first two and byte stores/loads for the weight table despite allocating four
bytes per element. The retained candidate fixes these accesses, keeps the
remaining-choice count as a promoted integer, and preserves the signed-byte views
of the per-slot mask. No runtime calls were removed.

The candidate's `s64 (u16 *, u8 *, s64)` signature agrees with the active caller
`002f9c30` in `y_fclCombine.c`. Pool insertion/removal and persona helper declarations
were checked against the current providers, with explicit views at the actual
consumers. The existing `0044ea90(file, line)` allocation-debug idiom still needs a
separate contract decision: the active SDK stub is defined as `void(void)`. This
frontier is not a claim that this pre-existing boundary is ready for integration.

The remaining mismatch includes loop-counter/weight-index normalization and
register lifetimes, plus the position of value captures across the assertion call.
Its 16-byte size deficit contains retail instructions; it is **not** permissible
alignment padding. All 35 relocations are resolved in the sealed residual report.

The bounded families in `lifetimes.py` cover promoted loaded values, separate weight
indices, natural inline weight/count/accessor helpers, counter widths, explicit
loop invariants, CSE/propagation/rebuild choices, unsigned totals and typed versus
byte-addressed word weights. Helpers and declaration changes were largely neutral;
broader optimization changes regressed. Do not rerun the 28 retained compilations
to recover their terminal output.

## Calendar state builder, `00313d20`

Owner: `src/promoted/code1_0031.c`.

`build/complete-20260921/fcl-independent/date/runs/typed-calendar-records/candidate.c`.

callers. Its only callee is the current `s64 func_00110a60(s32, s32)` provider;
the caller explicitly takes the signed-byte result view. The old archive's narrow
return spelling was not adopted. The active same-owner caller `00313b50` is among

The initial native seed measured 652 bytes, 129 masked words, and 61 alignment
edits. Improvements came from treating already signed-byte loads as promoted
integers, restoring the final loop's signed-halfword update, preserving real
selection-byte pointers, and capturing the raw mode at its individual consumers.
Disabling propagation preserves the sentinel and loop constants visible in retail;
the existing CSE-off context preserves the separate width views. The three-iteration
header loop intentionally reads the same row byte at offset 2 each time, as retail
does. It must not be replaced with an invented progressing record lookup.

The remaining 22 fully resolved differences are predominantly one register
assignment permutation in the explicit-calendar branch: table pointer, counter,
five-byte block offset/base, and the 100/1 constants. The count-base addition also
has commuted operands, and the counter increment uses a temporary before
normalization. The other branch's selection-store addressing is reproduced.
The 4-byte suffix after the 652-byte candidate is zero retail alignment only.

The 53 retained candidates cover width/loaded-value fixes, address association and
pointer lifetimes, explicit constants, declaration order, natural pointer helpers,
counter forms, lifetime analysis and ordinary register hints, wide loaded values,
parameter reuse, explicit loop bases, and word/record table views. The last families
did not improve 22 words. Using the typed record preserves the best result without
