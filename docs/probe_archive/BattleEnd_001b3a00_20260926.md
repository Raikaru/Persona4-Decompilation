`src/promoted/code1_001b.c` `func_001b3a00`: MATCH, 1268 bytes of code in the

Relocations: the battle-work pointer at gp-0x4C54 (`iGpffffb3ac`, also named

## What the old draft had wrong

- The 0x80 test wraps the whole body, so the early exit shares the final
  `return 0`.
- The state dispatch is `switch (state) { case 1: case 3: ...; case 2: ... }`
  and the default returns 0. At the end of the 1/3 body, `state` is re-read and
  `state == 1` returns `(flags & 2) ? 12 : 11`. Case 1/3 then falls into
  `case 2`, where `state == 2` is tested. Retail's case-2 entry jumps straight
  to that test.
- The flag test on the entry table is `*(s32 *)(... + ix * 0x18) & 0x2000`.
  The draft read a byte and tested 0x20.
- The rank lookup reads the table at gp-0x4BF0, not an offset from the work
  pointer.

## Levers

- In the state-1 branch, the "slot occupied" read `((s32 *)(D_0076449C +
  0xC84))[id]` uses the file's other name for the work pointer. Retail reloads
  the pointer there even though `$a0` still holds it. Written through
  `iGpffffb3ac` it CSEs and is one instruction short.
- The first unit loop and the second use separate cursor variables. Retail has
  them in `$s3` and `$s1`.
- `rank = func_00231e20(...) & 0xFF` is its own `s16` statement before
  `diff = CE0 - rank`. Otherwise the CE0 address is held across the call in a
  saved register, and the `(s16)` extension disappears.
- The s32 at 0xCE4 is passed directly to `func_0036ee60`'s `s16` parameter.
  This is what puts `lh a1` before `addiu a0`. With an explicit `*(s16 *)` the
  two are swapped (2 words).
- Declaration order `state, pick, unit, alive, total, hurt, member, status, diff,
  rank` gives retail's colouring (hurt `$s0`, total `$s1`, alive `$s2`, unit
  `$s3`, pick `$s4`). The first natural order was the exact reverse of this. It
  left 42 fnalign edits, all saved-register names.
- No pragmas. The old `opt_propagation off` wrapper is gone.
