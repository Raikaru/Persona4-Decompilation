# Sprite renderer 0046b380: guarded semantic recovery

`src/Kernel/sdkSpr.c` now retains a corrected native C draft behind
`NON_MATCHING`. **This is not an exact C match.** The physical owner compiles
to 7,840 target bytes against a 7,808-byte retail window, with 830 fully
resolved instruction-alignment edits. The default owner object is byte-identical
to the original assembly-backed object. No matching progress is claimed.

The previous draft had concrete geometry and color errors. The remaining work
also includes retail's unwritten coordinate inputs; a smaller diagnostic result
that preserved those reads was rejected as a matching solution.

## Recovered data contracts

The sprite loader allocates 0x80 bytes per record and copies exactly that extent.
Its 0x240-byte container owns 32 raster pointers at +0x104 and the record pointer
at +0x204. A sprite instance is 0x2c bytes. Its pivots are signed 16-bit values
at +0x1c/+0x1e, its optional scales are unsigned Q12 values at +0x20/+0x22,
and its RGB multipliers are bytes at +0x28 through +0x2a. The private helpers
retain the same unsigned extent and signed override behavior as the already
matched public width and height queries.

The vertex is the SDK's 64-byte `RwSky2DVertex`, including its real four-quadword
alignment overlay. Its screen coordinates occupy +0/+4/+8, UVs +0x10/+0x14,
reciprocal camera Z +0x18, and floating color channels +0x20 through +0x2c.
Camera/fog and normal storage remain part of the actual packet layout.

`RwGlobals.dOpenDevice` contains both callback slots. The state setter at
0x00887300 and primitive renderer at 0x00887310 are members of the same object
beginning at 0x008872e0. A faithful prefix of that object restores the callback
address lifetime seen in retail. The renderer's actual three-argument signature
is provided by `func_0040c0f0`; `func_0040d110` installs it. The primitive table
at 0x0070c2e0 resolves primitive 4 to `func_0040bac0`, whose four 16-byte loads
per vertex confirm the complete 64-byte extent.

The matrix and vector declarations follow the real providers. The rotation
entry receives the two floating arguments before its combine mode. The axis
at 0x007130d8 independently reads as `(0, 0, 1)` from the configured retail image.

## Semantic corrections

The initial quad now has the four distinct XY corners: `(-px, -py)`,
`(width-px, -py)`, `(-px, height-py)`, and `(width-px, height-py)`. The old
draft wrote several of these values into incorrect coordinates. UV flips now
exchange genuine two-component objects instead of byte ranges.

Packed record colors are red in bits 31–24, green in 23–16, blue in 15–8,
and alpha in 7–0. The old draft reversed this order. Vertex 2 reads the color
at record +0x70, vertex 3 reads +0x6c, and the first two use +0x64/+0x68.
Textured color expansion applies to alpha as well as RGB. The old guard omitted
that alpha operation. The repaired ordering is packed-color extraction, RGB
multiplication, textured channel expansion, alpha multiplication, and saturating
alpha subtraction.

The border calculations use their actual dimensions and retain full signed
border arithmetic:

| Border field | X range | Y range | Repeated texture edge |
| --- | --- | --- | --- |
| Top +0x34 | `-px` to `width-px` | `-(py+top)` to `-py` | Top row |
| Bottom +0x38 | `-px` to `width-px` | `height-py` to `bottom+(height-py)` | Bottom row |
| Left +0x3c | `-(px+left)` to `-px` | `-py` to `height-py` | Left column |
| Right +0x40 | `width-px` to `right+(width-px)` | `-py` to `height-py` | Right column |

The old draft mixed width and height in these strips, performed an unused
width query in the left strip, and narrowed border negation to a signed short.
The final vertical and horizontal stretch paths use the saved original quad;
vertical stretch retains priority. Horizontal stretch retains retail's integer
conversion of the original X coordinate before addition.

Extent conversion is consumed before pivot subtraction. Color conversion no
longer keeps an unrelated packet pointer alive. Independent copy and color
loops use their own iterators. These changes follow the data's lifetime and
remove large groups of register and scheduling differences without register
binding, padding, arithmetic assembly, or compiler-flag sweeps.

## Unwritten inputs and limits

Retail skips UV initialization when the initial raster is null but later reads
the local UV floats. The guarded draft bypasses those UV swaps and assignments
when no initial raster exists; it does not invent texture coordinates. A null
raster is bound for an untextured draw. Unused packet lanes still belong to the
SDK packet and are transferred as object representation by the renderer.

Retail also writes only XY before passing three-component vectors to
`func_003e42e0`. The real scalar `VectorMultPoints` provider reads Z and includes
it in all three transformed components. Direct callers such as
`func_0025ea20` and `func_0034f320` permit nonzero rotation, so no caller-level
zero-angle precondition can justify treating the omitted input as harmless.
The guarded draft explicitly defines the sprite's planar Z as zero. These
additional writes contribute to the measured nonmatch and are not claimed to
reproduce retail's unwritten storage.

The separately owned attachment transformer `func_0046a7f0` retains the same
unwritten-Z issue, documented in its existing archive. Border rendering still
calls that entry. Its implementation was not changed here; a claim that the
entire rotated-border call chain is defined still requires that owner review.

Before these input corrections, a diagnostic draft had 210 resolved alignment
edits, 7,756 bytes, and the retail 0x240 frame. It still contained unwritten
reads and a nonzero retail suffix. It is not a promotion candidate. The installed
draft has a 0x250 frame, is 32 bytes oversized, and has 1,833 differing resolved
words / 5,768 differing resolved bytes. Alignment-edit counts and positional
byte/word mismatch counts are different measures and must not be interchanged.
