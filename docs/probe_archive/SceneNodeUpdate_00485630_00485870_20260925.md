## What closed most of the gap

- **`#pragma opt_propagation off`** (push/pop around the function). Retail
  materialises the save slot's stack address into a scratch register at
  both uses (`addiu $v1,$sp,0x50` for the save and `addiu $v0,$sp,0x50` for
  the restore). With propagation on, every spelling either folds the address
  into `sq 0x50($sp)` or keeps it in `$s0` across the two calls. With it off,
  and the pointer assigned twice (`save_slot = &save;` before the save and
  again before the restore), the object is the exact retail size.
- **Float to VU0 through an operand.** `qmtc2.ni %0, $vf2` with `"r"(five)`
  / `"r"(scale)`: MWCC emits `mfc1 $v0,$fN` and the hazard `nop` itself, so the
  asm is only COP2 work and no longer clobbers `$2`.
- **The trailing 0x08/0x0C callback** called through the table expression
  directly (no function pointer temp), so the `lw $a0, 8(...)` argument load
  comes first, as in retail.
- In 00485870 (s32 `arg0`), write the field address as `arg0 + 0x50` (integer
  arithmetic). `(u8 *)arg0 + 0x50` under propagation-off hoists the address
  into `$s0` (126 edits).
