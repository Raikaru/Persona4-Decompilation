# Formation placement 001d1680 recovery

`func_001d1680` selects a formation from enemy dimension counts, assigns the
party and enemy slot indices, optionally snaps units to the formation grid,
and turns the two sides toward each other. The implementation is native C in
`src/promoted/code1_001d.c`; its two integer parameters agree with the actual
callers in `func_001b1d70` and `func_001d3760`. Retail does not consume the
second parameter.

## Reconstruction and storage

The previous guarded reconstruction dereferenced the battle-state pointer
twice, passed single scalar locals as vector/quaternion/count buffers, rounded
formation coordinates and unit scale unnecessarily, and entered the party
loop without first testing the list. The recovered body uses the actual
`iGpffffb3ac` pointer, three complete vectors, a quaternion, four halfword
counts, and separately named party, enemy and facing-list cursors. Dimension
products retain the retail float-to-integer-to-float conversion; formation
coordinates and capacity slack stay floating point.

The decoded retail table has 25 rows of 224 bytes. Each row contains four
24-byte party slots, five 24-byte enemy slots and four halfword counts. The
five-candidate enemy scan uses 5 as its failed-fit sentinel. Retail then writes
`sp + 0x90 + chosen * 4` without another bound check. Consequently the local
occupancy object has six cells, although the clear and both scans use only
the first five. This sixth cell represents the observed sentinel write at
`sp + 0xA4`; it is neither an invented initialization nor padding. The five-
and six-cell proposals have identical complete object bytes. The battle-init
caller also scans six incoming enemy record slots; no new five-enemy runtime
guard has been introduced.

`func_0019d210` shows that `0x180` and `0x184` are opposite ends of the same
enemy list, connected by `0xA6C`/`0xA68`. The count and placement traversals
therefore see that same list in opposite directions. The routine retains the
retail failure behavior when no fitting slot exists; it does not invent a
fallback table entry or return early. As in retail, the facing stage expects a
nonempty eligible enemy group: `func_00196040` leaves its output center
untouched when no unit qualifies. This recovery does not claim that arbitrary
empty or corrupted battle states satisfy that precondition.

## Compiler closure

The configured MWCC PS2 3.0.1 b210 profile is `-O2 -Iinclude`, with compiler
SHA256 `286548490e2e902cfef21dcf39cd5af23766731585d90dea747f8781eadcafd7`.
Scoped loop-invariant and lifetime optimization preserve the constant setup
and the independent lifetimes of the two slot scans. A signed 64-bit sentinel
comparison keeps its conversion separate from the 32-bit table-row arithmetic.
The selected halfword index is widened before assignment, independently of
the current array index. Both conversions preserve the values of their
halfword operands. Sharing the real radius-slack variable across the two
passes restores their float-register lifetimes. Declaring the chosen slot
before the enemy pointer closes the final saved-register pair.

These changes are ordinary C and measured compiler settings. No assembly,
volatile accesses, fabricated side effects, repeated stores or additional
executable suffix were added.
