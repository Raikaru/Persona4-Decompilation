# Map-shape renderer 002b0b10

The map-shape renderer constructs four corners for the cell's origin and
orientation, writes the existing screen-vertex buffer, and queues its draw
callback. MWCCPS2 b210 at the configured `-O2 -Iinclude` emits 1,412 bytes in
the 1,424-byte retail window. All eight relocations resolve exactly, followed
by twelve zero alignment bytes.

Four complete `YVec3f` corner objects preserve the retail 12-byte stride and
the zero middle component. The drawing loop reads each corner's X/Z values
into screen X/Y, converts the four unsigned color channels, and writes depth
and reciprocal Z. The complete render-device record supplies the near-depth
field. A scoped `opt_loop_invariants on` preserves the original invariant
loads while leaving the per-vertex depth read in its loop.

The caller and callee share the position, width, height, depth, origin, scale,
color, orientation and layer argument order. This interleaves the first depth
save and origin save correctly without changing any argument-bank values.
The already recovered `func_002afbc0` remains exact at 1,624/1,632 bytes with
all 28 relocations. Every other function and both existing data tables in
`y_smap.c` remain unchanged.

## Primitive queue contract

Final review found an existing mismatch: most callers declared the third
argument of `func_00461390` as a vertex pointer, while its provider and two
legacy declarations described an integer. Declaring an integer at the new
renderer changed argument preparation and also changed the existing
`func_002b25d0`. Those diagnostic candidates are not the accepted source.

The coherent contract is `u8 *(void *, s32, void *, s32)`. The provider now
describes its actual 0x30-byte allocated node, including the vertex pointer at
0x20, and obtains the list-link view after constructing the payload. This
retains the original parameter and list-cursor lifetimes. Its 284 native bytes,
all relocations and four zero tail bytes match retail; every sibling remains
unchanged. The two legacy declarations in `y_draw.c` and `y_CmbCardEff.c` now
agree. The latter uses a real pointer local for its vertex buffer and preserves
its original 1,204-byte renderer. All other authoritative queue declarations
already have the same pointer contract.

The map callback is stored through its actual two-pointer function type.
There are no added runtime effects, register bindings, assembly bodies, or
object-byte modifications.
