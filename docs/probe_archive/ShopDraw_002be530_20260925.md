## How the body was built

1. **m2c needs the jump tables.** Stage the asm with `.L` labels at all 49
   targets and a `.rodata` section holding `jtbl_00748930` (47 words) and
   `jtbl_00748910` (6 words). Give m2c a declaration-only context, with
   `func_002b2a60` written as `void (FclDrawColor *out, ...)`. Run it with
   `--valid-syntax` so field accesses come out as typed `M2C_FIELD` macros.
   The result has all 1,525 calls. The old draft was missing about 637 calls
   because it had been hand-mangled.
2. **Mechanical conversion.**
   - Turn `M2C_FIELD` into `*(T *)(work + off)`.
   - Turn `(s64)(x << 0x30) >> 0x30` into `(s16)`.
   - Colours: `c = func_002b2a60(...)` plus
     `*(FclDrawColor *)(t + 0x79) = c` (retail loads all four bytes and then
     stores them).
   - Positions: `sp = func_002b2970(x, y)` into `Vec2f` locals. Pass them to
     `func_002e0620` as `*(u64 *)&sp`, the idiom from func_002df4c0.
   - Rewrite unsigned-float conversion if/else pairs as `(u8)f` and `(f32)u8`.
   - `adda.s`/`madd.s` sites are `A + B * C`: b210 emits `adda 0,A`, and
     `msub` comes from `A - B * C`.
   - `ldr/ldl 0x2C` is `*(u64 *)((u8 *)func_002e04e0(h) + 0x2C)`.
3. **Structure.**
   - Move the default arm to the end and write `break` for
     `goto block_626`. States 0xD and 0x37 keep their own returns.
   - Write the 42 counting loops as `for` loops with `s16` counters.
   - `spC0` is `char[0x10]` and `spD0` is `char[0x80]`, the sprintf buffers.
     This is what put the frame at `-0x790`.
   - The eight `{id, 0}` message argument pairs at 0x668-0x6A0 are a local
     `{s32 v0, v1}` struct.
4. **The big lever was inlining m2c's `temp = work + i * 4` address temps**
   into the field expressions (`*(T *)(work + i * 4 + off)`), 28 sites. That
   alone went 2594 -> 708. It fixed the global colouring (`work` from `$s3`
   to `$s1`, `arg0` from `$s0` to `$s4`) because b210's own CSE temps colour
   differently from named locals.
5. **Table positions.** Retail loads each `D_0063F5xx`/`F6xx`/`F7xx` table
   entry into `$s0` before the draw call that precedes its two
   `func_002b2970` calls. Write `tbl = (f32 *) D_x;` at that point: 31 sites,
   placed after any colour store.
6. **Store-forwarded index.** State 0xE is `work[7] = 0; p = D_0063F9F0 +
   work[7] * 12;`. Retail's `dsll32 $v1,$zero,24` comes from forwarding the
   stored zero, not from a literal.
7. **Index order.** `lb idx; sll; addu idx, work` needs the integer form
   `(idx * 4) + (u32)work`, the de5a0 idiom. `lh 0xC16` indexing stays
   `work + idx*2`.
8. **Sign extension.** b210 re-extends every `s16` *local* when it converts
   it to int. Retail extends once, at the assignment, and then passes the
   value raw to int parameters. So the id temps are `s32` with an explicit
   `(s16)` at the assignment. Loop counters stay `s16`. Many callees return or
   take int in this unit (see the declarations below). That took 566 -> 469.
9. **Declaration order ranks the saved registers.** Sorting the locals whose
   m2c names carry a saved register (`temp_17`, `var_19`, ...) in descending
   register order, after the `sp` buffers, fixed the zero local (`$s2` ->
   `$s3`) and the full prologue: 350 -> 315.
10. Small fixed-shape levers: `func() > 5` gives retail's `slti $at` (`>= 6`
    gives `slti $v0`); call `func_002e7a60` in its own statement; a `u8`
    temp for the `func_00110810` argument.
11. `0x62` alpha stores are `u8`, which lets 0xFF be CSE'd into `$s0` like
   retail. The Vec2f copy at +0x2C is a struct copy. The two bank-to-draw
   colour copies from `work + 0xF3E + i * 4` are `FclDrawColor` copies. The
   loop bound `work[9]` is re-read after state 0x15's loop (b210 CSEs it
   with the last loop test).

## Remaining residual (302 edits)

At the previous bank the categories were: 142 branch-offset-only rows (they
follow length deltas), 87 unpaired, 73 register-only and 13 other. The object
is 14 instructions short. Per state the deltas are 0x11 -2, 0x15 -4, 0x16 -4,
0x25 -1, 0x2E -2, 0x33 -1, 0x34 -1 and default +1.

- **Loop rotation in 0x12/0x25.** Retail enters the `var_19` loops with a
  `b cond`. b210 rotates the loop because the counter is a known 0. This costs
  about 4 instructions plus the branch-offset cascade.
- **Per-call re-extension in 0x2E/0x25.** Retail sign-extends the id before
  every call. An int temp with an explicit `(s16)` cast gets CSE'd, and an
  `s16` local is re-extended in different places (the c44 model was 433,
  worse).
- **Recomputation in 0x15.** In the else arm retail recomputes `(s16)i` into
  `$v1` and `&F58`/`&F6A`, where the object reuses `$s0`. The register swaps
  in 0x16 and 0x28 are similar.
- **F18 address CSE in 0x33/0x34** (4 sites).
- **Indexed-handle recompute in the 0xE/0x16/0x36 loop tails.** This looks
  like `func_002e0620(handle, func_002b2970(..), func_002b2970(..), ...)` with
  `Vec2f` parameters. That is a file-wide prototype change affecting matched
  func_002df4c0. A `temp_hp` pointer local made it worse (389).
