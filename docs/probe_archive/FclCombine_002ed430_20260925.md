## Levers that moved it (in order of size)

1. **Struct access for the task work block** (`*(FclCombineWork **)(arg0+0x38)`,
   fields `f1`, `f11E`, `f128`, `f148`, ...). The m2c `(*(T *)((u8 *)p + off))`
   spelling made MWCC CSE field addresses into saved registers
   (`addiu $s1,$s3,0x148` / `lw $a0,($s1)`); retail always uses `off($s2)`.
   fnalign 2298 -> 1301.
2. **`(s64)(x << 0x30) >> 0x30` on `s32` is undefined** and MWCC folds it away
   (it deleted whole loop bodies). Rewrite as `(s16)x` / `(s8)x`.
3. Drop m2c's mid-switch `default: return;` (it moved the epilogue target) and
   write m2c's `goto loop_N` as plain `for` loops: retail enters every loop with
   `b cond` (bottom test). The earlier do-while conversion was wrong here.
4. Colors: `FclDrawColor c = func_002b2a60(...)` and struct stores
   `*(FclDrawColor *)(p + 0x85) = c;` give the retail `lbu x4 / sb x4`.
   Declare the color locals highest-address-first (`col25C` first).
5. Title positions are `FclVec2f` struct copies (`lwc1/lwc1/swc1/swc1`) to
   0x138..0x158, not two `f32` locals (those went to `$f20/$f21`).
6. Loop counters are `s16` (MWCC re-extends at every use, as retail does).
   **Use m2c's register-suffixed names per loop**: 0x24 `var_16` ($s0),
   0x26 `var_19` ($s3), 0x2A outer `var_19_2` ($s3). Sharing one variable
   between loops that live in different retail registers broke allocation
   (0x24: 19 -> 11 edits, 0x33: 12 -> 0 after splitting).
7. **Narrow through the prototype, not with a cast.** `func_003191c0` and
   `func_0031ac10` take `s8` for the row; with explicit `(s8)i` MWCC CSEs the
   conversion into a saved register across the intervening call, retail
   converts at each call. -96 edits.
8. Hoist call-derived byte arguments into a temp right after their call
   (`slotByte = *(u8 *)(func_002e48a0(...) + 4)`, `partyCount =
   *(s8 *)(func_002e4870(0) + 8)`): retail loads them into `$t1`/`$t3`
   immediately after the `jal`. -40 edits.
9. Byte loads kept in named temps and then compared/subtracted must be `s32`,
   not `u8` (a `u8` variable is re-masked with `andi 0xff`).
10. `extern u16 D_008C024C;` is gp-relative (sdata); declare `[]` and use `[0]`.
11. `D_00640C10` is held in `$s0`: `basePos = (FclVec2f *)D_00640C10;`.
12. `iGpffffb3d4[x * 14 + 2]` (array subscript, as in fclCombineMisc.c) gives
    retail's `addu idx,base` operand order; pointer `+` gave the reverse.
13. Prototypes: `func_00317240(u8 *, s32, f32)`, `func_002bb1c0` returns `s32`,
    `func_002b2cb0/2d00` take the raw `lh/lb` field (no `(u8)` cast).
14. Declaration order moves saved registers as documented: `var_19_3` first,
    `temp_19_10` before `var_17_9` (0x37: 35 -> 7).

## Remaining blockers (not solved)

- **Case 0x2A branch recomputation.** Retail computes `i + 0x270` once for the
  alpha lookup (`$s7`, reused by the final `func_002b68d0`) and *again* at the
  top of each of the three colour branches (`$s6`, and in branch 1 a
  compiler spill `sq $v0,0xd0($sp)` / `lq`). Our object CSEs every branch copy
  with the alpha temp, so there is no spill, the frame is 0x250 (retail 0x260;
  every stack local is 0x10 low) and 0x2A's saved registers cascade.
  Tried without success: operand swaps (`0x270 + i`), `(s16)`/`(s32)` casts,
  `s16` for either temp (becomes `sh` spill or re-normalises), a block-local
  `row = i` (coalesced into the loop register), re-assigning a shared `row`
  per branch (coalesced), an `s32` loop counter with explicit `(s16)` casts
  (all extensions disappear), `#pragma opt_propagation off` (758 / 1020).
- Title `func_00275820` calls: retail loads `pos.y` (`lwc1 $f13`) right after
  `$f14`; ours loads it after the integer arguments (7 sites). A
  `static inline` title helper produced identical code.
- `func_003144d0(..., p->f2E4, ...)`: our `lb $a2,0x2e4` is scheduled before
  `lw $a0,0x148`; retail loads in argument order (3 sites). A typed slot
  pointer and hoisting the `func_00311930` call did not change it.
- 0x2A `x < 0 || x >= 6`: retail `slti $at` + `bnez $at`, ours `slti $v1`.

## Method

`FclCombine_casealign_20260925.py.txt` (run from the repo root:
`python <it> func_002ed430 body.c 0x749110 21 15056 [--dump cN]`) cuts both streams at the jump-table targets, aligns each
case on mnemonics only and counts register/immediate differences inside
aligned runs. Whole-function difflib (fnalign) mis-pairs the near-identical
colour branches and reports large phantom deletes. A greedy declaration-order
search (move one local, keep if the total drops) found nothing in ~60 minutes
on this body; the two ordering wins above were found by hand from the
register confusion table.
