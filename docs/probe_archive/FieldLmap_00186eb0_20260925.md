## Levers

- **`static void func_00186e10`.** It has one caller, this function. Once
  it is a static defined earlier in the TU, MWCC knows it leaves `$a0`
  alone, and the caller does not reload `$a0 = st` before
  `func_00188200(st, st + 0x90)`. Retail has no reload there. As a plain
  extern the object has an extra `move $a0, $s1`.
- **The camera matrix copy is a 64-byte struct assignment.**
  `*(FldLmapMatrix *)*(u8 **)(st + 0x18) = *(FldLmapMatrix *)func_0014b450();`
  compiles to retail's eight-iteration two-word copy loop, with both loads
  ahead of both stores. The hand-written word loop interleaved them.
- **`D_008C024E` and `D_008C0252` are `u16[]`**, as every other file
  declares them. Declared as scalars they were assumed small-data and read
  gp-relative. Retail reads them with `%hi`/`%lo`.
- **The 12-byte zeroing loop counts a `u32` n.** With a signed count, MWCC
  turns `n != 0` into `bgtz`. Retail has `bnez`.
- **The single-use panel-array accesses are subscripts**
  (`((s32 *)(st + 0x80))[side]` and the like). A subscript puts the index
  first in the `addu`.
- **The two scroll updates go through a panel slot:**
  `s32 off = !side * 4; u8 *slot = (u8 *)(off + (s32)st);`, then
  `*(f32 *)(slot + 0x88)`. This keeps retail's shape: the slot base is
  CSE'd and 0x88 is folded into both the load and the store. The integer
  addition puts the index first in the `addu`, which is the `matching.md`
  "name the offset in a local" recipe. The subscript form CSEs the whole
  element address instead, and pointer arithmetic puts `st` first.
