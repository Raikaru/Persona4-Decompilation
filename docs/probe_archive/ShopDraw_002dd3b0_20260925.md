## Prototype contract

The item id is an `s32` (`id = func_002e2830(...)` narrows the s16
result once). Retail passes it unextended to `func_001067f0`,
`func_00106880`, `func_00106b80`, `func_001068b0`, `func_001068e0`,
`func_00106940`, `func_00106970`, `func_00106600` and `func_001069d0`,
and extends it only for `func_00106a90`. With the getters declared
`(s16)` every one of those calls gains a `dsll32/dsra32` pair and the
function needs two more saved registers (750 words); an `s16` id instead
extends it for the int callees (989 words).

So the unit-scope prototypes changed: the six getters take `s32`, and
`func_00106cd0` returns `s32` (func_002d5040's stat delta passes its result
to `func_001068b0` unextended). The call sites where retail does narrow
now say so with `(s16)`: the `func_00106cd0` results passed to
`func_001067f0` (func_002d5040, func_002de5a0) and to the stat getters
(func_002d5040). Every other function in the unit keeps its status.
