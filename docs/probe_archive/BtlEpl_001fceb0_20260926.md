# func_001fceb0 (btlEPL.c) — MATCH (2026-09-26, campaign g1 round 4)

Size 2256B. The old draft stood at 314-329 words. It was a fresh rewrite on
the shared btlEPL types (BtlEplColor/BtlEplRgba, btlEplRgbaToV4, 1/255
literal). See BtlEpl_001fec00_20260926.md and BtlEpl_001fc630_20260926.md.

Shape:
- BtlEplFade2Param: total, fadeIn, fadeOut, and `BtlEplRgba color[2]` at
  0x08/0x0C. dst = func_001b7030() and src = func_001b7040() are both called
  after the early return and before `mode = 0`.
- Case 1, first pair: convert color[0] into a V4 with the helper, then
  `inv = 1 - scale`, then a0..a3 = target*inv, b0..b2 = c*scale, b3 = c[3]
  unscaled, and `dst.v[3] = a3 + b3 * scale`. Only this last component
  fuses.
- Case 1, second pair: all four a-products come first. Each b is written as
  `(1/255)*(f32)(u32)byte * scale`. The sums are written as
  `a0 += b0; dst[1].v[0] = a0;` with add and store interleaved. This puts
  each sum in its a-register ($f2/$f1/$f0) as retail does. Measured:
  `dst = a + b` gave 38 words, and accumulating everything before the
  stores gave 8.
- `#pragma opt_dead_assignments off` scoped to the function. Without it
  the result is 189 words.
- Case 2 uses the fec00 temporaries blend twice (src*inv + target*scale).
