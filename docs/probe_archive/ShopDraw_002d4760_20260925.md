## What closed it

- `extern const s8 D_00748908[];` and `func_002e26f0(slot) <= D_00748908[i]`
  (from the second-pass draft): the table byte stays in `$s1` across both
  calls.
- Out-of-range block: the [1]/[2] addresses of each row as block locals
  (`u8 *a2p = &colorA[i][2]; u8 *a1p = &colorA[i][1];`, declared in that
  order) and the chain `colorA[i][0] = *a1p = *a2p = v`. That gives retail's
  `a1 = row; a0 = a1+2; v1 = a1+1` with the inner `i == 1` stores through
  them. The colorB row takes the same shape in its own block; `cb =
  colorB[i]` instead shares `i*4` with the slot address across the call.
- Selected-row block: `colorX[i][0] = v; gx = colorX[i] + 1; *gx = v; bx =
  colorX[i] + 2; *bx = v;` with `ga/ba/gb/bb` function locals, which puts
  the four [1]/[2] addresses in `$s0/$s6/$s7/$fp` across the second call.
  In the inner block the [0] byte goes through `(u8 *)colorX + i * 4`; any
  `colorX[i]` spelling there is CSE'd with the row address above and kept
  in a saved register (spilling a variable).
- Separate loop counters: `i` for the setup loop and `j` for the draw loop.
  With one `i` the counter and `sel` swap `$s4`/`$s5` in loop 1 (12 words);
  declaration order and `sel` placement are inert.
