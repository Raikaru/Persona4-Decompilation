# Scene render queue: guarded recovery at 0x00148280

`src/promoted/code1_0014.c` retains an improved ordinary C reconstruction of
`func_00148280` behind `INCLUDE_ASM`. The candidate is **5016 bytes in a
5024-byte retail window**, with **21 fully resolved differing instruction
words / 22 bytes** and eight bytes of retail zero padding. It is not an
accepted C match. Production remains **124 MATCH / two ASM** for this owner;
this change adds **zero production matches**.

The recovery starts from worker-2's measured `head_snapshot.c`. Worker-1
reviewed the complete owner, full retail listing, both decompiler guides,
registration caller, queue allocator/provider, model renderer, and previous
probe archives. Twenty-five additional targeted variants did not improve
that candidate. The best recovery was then retained in its actual owner,
with obsolete guard commentary and unused locals removed.

## Recovered behavior and call contracts

The callback keeps its actual `s32(u8 *)` task contract, including its early
return and final zero result. The adjacent `func_00149620` registration
continues to pass it directly to the task allocator. The two local sort
arrays still contain 64 pointer slots each. The position temporary is the
existing complete `RwV3d` type; fallback placement copies all three matrix
position components before adding `175.0f` to Y.

Each traversal owns its counters and resource snapshots. The attachment
predicate and immediate bone-position call share the snapshot that retail
loads before the call. Resource contents are loaded again after callbacks,
including before the fallback matrix query and final attachment-position
update. The sorted slot's address can remain stable while the value stored
in that slot is reloaded. Cached values were not extended across calls that
retail follows with a new load.

The recovered control flow preserves the result check on `func_0014a160`,
the masked resource-ID threshold of 100, the opaque and sorted render passes,
and the queue setup/restoration callbacks. It also preserves the retail
list-2 branch that sets `flag3` and continues without advancing the current
node when bit `0x04000000` is set. That unusual path was not silently changed
as part of the source recovery.

The two actual `qsort` providers, `func_00148000` and `func_00148140`, now
accept `const void *` element arguments and use local `u8 *const *` slot
views. The guarded caller declares `qsort` with `size_t` count/size and a
compatible comparator function pointer, then passes each comparator directly.
The prior data-pointer casts are removed. A search of active source and
headers found only these two local sort calls. Both comparator bodies remain
**316 bytes in 320-byte windows**, with zero resolved differences and all ten
relocations checked for each. Their existing optimization pragmas are intact.

## Remaining two loop lifetimes

The first final sorted draw loop exchanges the saved registers used for
the current array slot and its attachment counter. Its nine differing words
are at target-relative offsets `0x1064`, `0x1068`, `0x10b0`, `0x10bc`,
`0x10c0`, `0x10f0`, `0x1130`, `0x1148`, and `0x114c`.

The second loop keeps the predicate's slot address alive through the queue
allocator, where retail forms a transient predicate address and later
computes the slot again. Its slot and attachment counter also receive
different saved registers. Its twelve differing words are at `0x1178`,
`0x117c`, `0x11d0`, `0x11d4`, `0x11ec`, `0x1204`, `0x1210`, `0x1214`,
`0x1244`, `0x1284`, `0x129c`, and `0x12a0`.

All other resolved target bytes agree with retail. The receipt records
every differing word and every target relocation. These register and
lifetime differences still prevent promotion.
