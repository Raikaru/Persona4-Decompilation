## Resource and callback lifetime

The relevant callers and providers were read alongside their retained retail
assembly. Two path values were read from the SHA-1-validated retail ELF:

| `00712880` | `camp/icon.ico` | `h_memcard_grouped.c::004647c0`, phase 1 lookup |

`mc.c::002a4b10` stores the archive handle in work offset `0x3a4`. Its state 4
waits for `H_Cdvd_IsFileLoaded` before advancing; state 6 runs `002a4570`, which
dispatches the save flow through `002a34e0` to `004647c0`. The teardown callback
`002a4cb0` obtains the task's work allocation through `00452560`, releases the
archive handle, then clears the field. Thus the intended save flow retains the
archive handle while the asynchronous card writes are polled.

`sdkCdvd.c::00454640` calls `00455b70` to register archive members and then sets
`readState = 4`. `H_Cdvd_IsFileLoaded` tests exactly that state.
`h_cdvd.c::00455b70` reads 0x100-byte archive headers, registers each member's
buffer, length, owner and normalized path through `00455d70`, and returns
normally at an empty filename. Registration precedes the completed-load state.
The destroy paths invalidate cache entries associated with the released owner.

This establishes the intended buffer lifetime; it does not establish member
presence. An archive ending before an `icon.ico` entry can still reach the
completed-load state. `sdkCdvd.c::00455f70` scans 256 registered resources and
returns zero without writing its size output when no path matches. In retail
assembly, the output store is at `00456048`; the unsuccessful scan returns zero
at `00456074`. The target reads its independent icon-size slot at stack `0x10`
after the lookup. A prior asynchronous poll does not initialize that slot.

No `camp/icon.bin` asset or member inventory was found in the assigned worktree.
The prime separately reported that the approved parent `orig` directory
contains only `SLUS_217.82` and `SYSTEM.CNF`, with no icon archive.
To justify an unchecked source expression, the continuation must establish a
valid registered `camp/icon.ico` member and its retained lifetime, rather than

## SDK contracts and state semantics

SDK provenance identifies `00431d78` as `sceMc2SearchFileAsync` and `004323a8`
as `sceMc2CreateFileAsync`. Both retail wrappers return a signed 32-bit status;
their early failures materialize `0x8101xxxx` values and their successful exits
return zero. The owner's previous `void` declarations hid those real returns.
The retained contract-only probe changes them to `s32`, with a `const char *`
path parameter. Those two declaration corrections were applied after the prime's
explicit authorization. Their callers still ignore the status, as retail does.
Actual production and guarded compilations after the change produce the
identical respective pre-change owner objects.

The other operations are the SDK's format, get-info, write-file and mkdir
asynchronous calls. The write wrapper records the buffer pointer, unsigned
offset and unsigned length in its queued request. Existing unsigned write
arguments were preserved. `00464670` passes real command/result output pointers
to `sceMc2CheckAsync` and normalizes its signed result. The target consumes poll
outputs only on completion. The deliberately redundant state-4 result test
and sparse physical state order were preserved from retail.
