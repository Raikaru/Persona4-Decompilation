# Translation units that retail built with ee-gcc 2.96 rather than MWCCPS2.
#
# Evidence: every function in these files saves callee-saved `$s` registers
# with `sd` in its retail prologue.  MWCCPS2 3.0.1b210 emits `sq` at every
# optimisation level in all three builds present on disk, and its MIPS BackEnd
# has no option that changes it -- so these functions are unreachable with
# Metrowerks and reachable with ee-gcc 2.96 at `-O2 -G0`.
#
# ee-gcc 2.96 was pinned, not guessed.  2.95.3 emits `sq` for callee-saved
# registers, and 3.2 colours a scratch base register `$t7` where retail has
# `$v0` (func_00509910/func_0050cce0); 2.96 reproduces both exactly.
#
# The two compilers separate cleanly by file: these units contain no MWCC
# functions.  code1_0041.c is 66 GCC / 24 MWCC with a single transition in
# address order and code1_0044.c is 53 / 1; both need splitting before they
# can be listed here.
#
# Anything listed here is built by tools/eegcc_shim.py in both tools/verify.py
# and tools/build.py.  Nothing else changes.
#
# A unit is listed once ee-gcc is a net win for it.  Moving a file here costs
# any existing C body that was written to MWCC's register allocation and does
# not reshape, so each one was measured both ways first.  These five gained:
#   code1_004e +3   code1_004f +8   code1_0050 +7
#   code1_0052 +3   code2_0070  0 (no C bodies; it links, which proved the path)
#
# code1_0051 measured +13 but cost func_005131b0, which matches under MWCCPS2
# and has no ee-gcc spelling: retail keeps a full frame around the call where
# ee-gcc emits a tail call.  A net gain is not worth a regression, so it stays.
#
# Four more are pure ee-gcc but are NOT listed, because on measurement they
# lost more than they gained: code1_0042 -14, code1_0043 -4, code1_004c -1,
# code1_004d -1.  Their MWCC-shaped bodies match today and the ee-gcc spellings
# for them have not been found.  code1_0041 and code1_0044 are mixed units and
# need splitting at their single GCC/MWCC transition before they can move.
#
# All of these are prebuilt vendor libraries (see VENDOR_CODE_RANGES in
# tools/verify.py), so this list moves the tree-wide count, not first-party.
